# Architecture

Phase 3.3 adds [on-device dictionary handwriting](android-handwriting.md), using a
back-stack ViewModel and a dedicated ML Kit adapter. Selected candidates feed the existing
dictionary query pipeline; recognition adds no backend operations or learning progress.

Phase 3 adds the [Vocabulary Lesson Player MVP](vocabulary-player.md): typed bundle
mapping, five scene renderers, temporary handwriting and a transactionally saved resume
cursor. The historical Slice 1/2 descriptions below describe the earlier preview controls;
published content still carries preview-only completion semantics.

The scaffold contains one Android Gradle app module and one independently runnable API.
The implemented Android slice is Compose → ConnectivityViewModel → HealthRepository →
RemoteHealthRepository → Retrofit → GET /api/v1/health → immutable UI state.
Loading, success, unavailable and retry are implemented. Slice 2 adds actual authentication
and preview access as described below; other future features remain explicit placeholders.

Backend Slice 1 adds a local JSON authoring workflow: typed validation, transactional draft
import, immutable versioned template scenes and content-addressed preview publication.
See [content authoring](content-authoring.md). It adds no HTTP endpoints or Android learning
behavior. The nine original tables expand to fourteen; uncertain legacy learning records
are retained without claiming verified TEACHES provenance or changing SRS schedules.

Android uses Hilt constructor injection, lifecycle-aware StateFlow, Navigation Compose,
and Material 3. Domain contracts and models contain no Android framework dependencies.
`core/database` holds a public vocabulary cache and DAO. `feature/vocabulary/data`
maps cached rows to domain models; no network vocabulary API is invented.
DataStore contains only non-sensitive device preferences. The original Material theme,
launcher assets, application ID and `com.example.chineselearningapp` package are retained.

FastAPI routers own HTTP contracts; Pydantic schemas define JSON, SQLAlchemy models define
persistence, and dependencies provide async sessions. Concrete repositories and business
services are introduced for Slice 2 authentication and learning access. Async psycopg is used by
both application sessions and Alembic. The API does not connect to PostgreSQL until a
database operation is requested; liveness is intentionally independent of the database.
Unexpected errors receive a generic 500. Application logs are JSON events without
exception messages, request bodies or credentials. Start Uvicorn with `--no-access-log`
and the supplied `--log-config logging.json` to avoid recording sensitive query strings
or exception traces. `python -m app` applies the same configuration. CORS defaults to no browser origins.

## Structure decisions

- Existing Android source, wrapper and resources moved into `android/`; existing package
  name retained instead of the example `com.example.chineselearning` to preserve identity.
- Original AGP 9.0.1 / Gradle 9.2.1 retained. Compose compiler aligned with AGP's built-in
  Kotlin 2.2.10. Java source/bytecode target is 17, Gradle daemon target is 21.
- Shared placeholder rendering and destination metadata avoid seven duplicate screen classes.
  Feature packages without behavior have boundary READMEs, not empty Kotlin classes.
- No empty `usecase` or `common` layers. Existing theme remains under `ui/theme`;
  shared UI components live under `core/designsystem`.
- Authentication and synchronization boundaries are documented, without fake adapters.
- UUIDs are generated by application code; timestamps default to PostgreSQL `now()`.
- Backend dependency ranges describe compatibility; `requirements-dev.lock` records
  exact resolved versions for the validated development environment.

## Slice 2: sessions and preview access

Email/password replaces Google Sign-In as the MVP authentication priority. Google linking
is deferred until pre-release. Password credentials are separate from the unchanged user
UUID/legacy email namespace. Additive revision 0003 introduces password_credentials,
auth_sessions, refresh_credentials, lesson_runs and lesson_scene_progress (19 tables total).
No legacy data is converted, merged or deleted. See [authentication](authentication.md).

FastAPI routes use Pydantic input, request-scoped async SQLAlchemy sessions and concrete
transaction-owning authentication/learning services. Opaque access/refresh credentials
are persisted only as digests. Refresh-family locking serializes rotation and replay
revocation. Every personal read/write derives its owner from the authenticated session.
Immutable published bundle bytes are verified through the existing storage adapter;
file reads and password hashing run outside the event loop.

Android adds SessionRepository → Retrofit/Keystore persistence → SessionViewModel → Compose
registration/login and preview-run controls. StateFlow is immutable and lifecycle-aware;
coroutine cancellation propagates. The repository serializes refresh and session operations,
maps DTOs to domain objects and keeps all network/storage access out of composables.
Successful login navigates to Home. Rejected refresh returns to login and clears private
state; transient errors permit retry. No personal Room tables or synchronization are added.

Preview runs pin one published lesson version. Scene checkpoints are bounded bookmarks,
with membership checked against that exact bundle. No completion endpoint/field, EXP,
mastery or SRS writes exist. The server and client must explicitly permit preview access.
The original health demo and local authoring/publication workflow remain available.

## Authentication and Home UI

SessionViewModel exposes explicit Restoring, RestoreFailed, SignedOut and SignedIn states.
SessionNavigation renders mutually exclusive navigation graphs, keyed by identity; switching
accounts or logging out removes all protected back-stack state. Restoration completes before
any form appears, and a retryable connection error does not masquerade as a missing session.
Home, Login/Registration and PreviewLessonsScreen are separate renderers. Shared Material 3
colors, typography, shapes, spacing and actions live in ui/theme and core/designsystem.
Catalog/run errors do not undo an authenticated account. No new database schema, provider,
credential mechanism or learning completion behavior is introduced by the UI revision.

## Main navigation and Profile

The authenticated graph uses one Navigation Compose controller with four top-level tabs:
Home (Trang chủ), Learning (Học tập), Review (Ôn tập), and Profile (Hồ sơ).
Tab switching pops to Home with saveState, launchSingleTop and restoreState; reselecting
the active tab is a no-op. Back from another tab returns to Home. Scroll state and the
selected destination use Compose/Navigation saved state. Preview catalog, vocabulary,
connectivity demo and player remain detail routes without bottom navigation. Login and
registration retain their separate controller outside the authenticated shell.

Profile renders only available SessionState account fields and owns the sole logout
entry point. A saveable AlertDialog confirms the existing SessionViewModel.logout call.
Loading disables repeat submissions; server/network failures keep the account and show
the existing error for retry. Successful revocation clears the existing repository and
ViewModel session data and removes the identity-keyed protected graph, including saved
tab history. Home has no logout callback. Learning and Review add no roadmap/SRS logic
or synthetic progress; Learning links to the existing preview catalog.
