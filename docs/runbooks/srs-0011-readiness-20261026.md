## Phase 4.1B integration plan only

After confirmed deployment and verification, implement the actual ordered engine:
Vietnamese meaning → entered Simplified Hanzi → tone-correct entered Pinyin → selected POS.

1. Resolve a reviewed, versioned sense policy with an unambiguous Vietnamese prompt,
   accepted Simplified/Pinyin answers, and accepted POS choices. Pin catalog UUID,
   content version/checksum, sense key and policy version to the existing attempt.
2. For this requested three-stage mode, require all three stages to be available before
   enabling grading. The foundation supports optional POS, but that capability alone
   does not satisfy this mode. Missing trustworthy POS or ambiguous prompts leave the
   exercise unavailable until reviewed policy exists; never synthesize answer sets
   from raw delimiters or gloss order. Preserve the saved word and its schedule.
3. Define authenticated, owned stage-submission input as attempt ID, stage, raw answer
   and idempotency key. Persist first submissions and hints/reveals server-side. Reject
   client verdicts, mastery, timestamps, target policies and schedule eligibility.
   Final route names and any additive persistence migration are a 4.1B design step.
4. Specify normalization and acceptance for Hanzi whitespace/punctuation, Pinyin marks
   versus numbers, ü/u:/v, neutral tone and sandhi, and reviewed POS identifiers. Grade
   actual answers against the pinned policy on the backend.
5. PASS requires all HANZI/PINYIN/POS first answers correct and unaided. One failed
   stage, hint or reveal makes the overall attempt FAIL. A clean incomplete attempt
   cannot PASS. Define abandonment, expiry, retry and repeated-submission behavior.
6. Construct `ValidatedReview` only inside `ReviewEvaluator`; finish through existing
   `complete_validated`. Retain locking, generation checks, immutable history, atomic
   commit and identical replay behavior. Keep every approved scheduling rule unchanged.
7. Verify grading/normalization, order, assistance, auth/isolation, replay conflicts,
   concurrent completion, stale attempts and rollback with isolated fixtures; then wire
   Android state and screens as a separately implemented 4.1B slice.

Remaining deployment gate: explicit operator confirmation. Remaining 4.1B work:
